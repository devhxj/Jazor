# 混编项目编辑反馈基线

在仓库根目录构建 Release CLI。以下 PowerShell 示例使用 Edge，其他平台请传入对应的 Release CLI apphost 与 Chromium 路径。

```powershell
dotnet build src/Jolt.Cli/Jolt.Cli.csproj -c Release
$jolt = (Resolve-Path src/Jolt.Cli/bin/Release/net11.0/Jolt.Cli.exe).Path
$chromium = 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'
dotnet run --file scripts/csharp/verify-jolt-mixed.cs -- $jolt $chromium --benchmark 20
dotnet run --file src/Jolt.LanguageServer/verify.cs -- --benchmark-mixed 10 $jolt
```

- 浏览器使用实际混编样例的独立临时副本。每轮交替保存 `MixedEditor.jazor` 的标题和 `NameInput.vue` 的标签文字。从开始写文件计时，到收到 Chromium 返回的 DOM 变更和状态检查结果。每次写入使用不同文字，并验证同一个输入节点保持焦点、未保存文本保留、父组件状态等到输入框失焦后才更新。
- 编辑器通过 LSP 发送增量 `didChange`，等待对应 `.jazor` 文档版本、源码位置及诊断编号。依次测量 C# 表达式拼写错误及修复、依赖 SFC 的 `limit` 属性从 `number` 改为 `string` 后调用方出现错误及修复。
- 两个程序都输出 JSON 原始样本和最近秩 p50/p95。浏览器单独报告首轮交替编辑，LSP 单独计时初次诊断并在采样前预热一轮。新工作区的 pnpm 还原使用本机已预热的内容寻址存储，Dev Ready 记录启动 Release CLI 到 Vite 输出监听地址的时间。浏览器使用独立的临时配置文件。
