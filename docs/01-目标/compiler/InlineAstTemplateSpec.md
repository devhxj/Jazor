# Inline AST Template Spec

## 1. 决策结论

对于白名单 `Op.Inline`，本项目后续统一采用：

- 外部接口仍保持字符串模板
- 内部实现改为“模板预解析 AST + 占位符替换”

明确不再继续沿用：

- 参数 AST -> JavaScript 字符串
- 字符串替换
- 再次 `ParseExpression`

这个旧方案只保留为历史实现背景，不再作为未来扩展方向。

## 2. 设计目标

新的 `Inline` 实现必须同时满足：

1. 不破坏现有 `[Jazor(Op.Inline, "...")]` 的书写方式
2. 参数始终以 AST 形态参与替换
3. 模板只解析一次，不做重复 parse
4. 对对象字面量、逗号表达式、`new`、索引、可选链等结构保持稳定
5. 为复杂宿主映射预留退路，允许升级到 `Op.Compile`

## 3. 模板语法

模板字符串占位符统一使用：

- `__arg1`
- `__arg2`
- `__arg3`

但在内部预处理阶段，应把它们规范化为“保留标识符”：

- `__jz_arg0`
- `__jz_arg1`
- `__jz_arg2`

要求：

- 这些保留标识符只用于模板 AST 内部
- 任何真实用户符号不得与该前缀冲突
- 若模板中出现同名真实标识符，应视为模板非法

## 4. 生命周期

### 4.1 初始化阶段

对白名单条目做一次性处理：

1. 读取 `Inline` 模板字符串
2. 把 `__argN` 规范化为 `__jz_arg(N-1)`
3. 调用 parser 解析为模板 AST
4. 缓存模板 AST

### 4.2 调用阶段

每次实例化模板时：

1. 从缓存取模板 AST
2. 深拷贝模板 AST
3. 遍历克隆树
4. 把 `__jz_argn` 替换为真实 `Expression`
5. 返回实例化后的 AST

调用阶段不应再进行字符串拼接或 parse。

## 5. 替换规则

### 5.1 基本规则

当遇到：

- `Identifier("__jz_arg0")`

应替换为对应的真实参数 AST。

### 5.2 替换粒度

替换必须发生在 AST 节点级，而不是 token 级。

允许替换的位置包括：

- 二元表达式操作数
- 调用参数
- 成员访问对象
- 索引器对象或索引参数
- 条件表达式分支
- 对象/数组字面量值
- `new` 表达式参数

### 5.3 不允许的模板形式

下列情况不应由 `Inline` AST 模板承载：

- 占位符出现在标识符片段内部
- 需要按参数 AST 类型分支
- 需要生成多条语句
- 需要引入临时变量
- 需要显式控制 `ref/out` 协议

这类情况应直接改用 `Op.Compile`。

## 6. 缓存策略

推荐增加专门缓存层，例如：

- `InlineTemplateCache`

缓存键建议直接使用：

- 白名单成员签名

缓存值建议包含：

- 原始模板
- 规范化模板
- 预解析 AST
- 占位符数量

目标：

- 同一模板只 parse 一次
- 调用阶段只做 clone + replace

## 7. 与 `Op.Compile` 的边界

### 7.1 继续使用 `Inline` AST 模板的场景

适合：

- 简单宿主表达式映射
- 纯表达式组合
- 不依赖参数形状判断
- 不需要副作用顺序重写

### 7.2 必须升级到 `Op.Compile` 的场景

必须升级的典型信号：

1. 需要根据参数 AST 类型决定生成结果
2. 需要引入临时变量
3. 需要生成多步 Sequence / Statement
4. 需要控制导入或宿主依赖
5. 需要避免重复求值
6. 需要处理 `ref/out`

结论：

- `Inline` AST 模板解决“结构稳定”
- `Op.Compile` 解决“语义复杂”

两者不应互相替代。

## 8. 测试要求

切换到 AST 模板后，至少补以下测试：

### 8.1 结构敏感参数

- 对象字面量参数
- 数组字面量参数
- `new` 表达式参数
- 逗号表达式参数

### 8.2 访问路径参数

- 成员访问参数
- 索引访问参数
- 可选链参数

### 8.3 复杂现有语法交互

- tuple 参数
- pattern 结果参与 `Inline`
- collection/object initializer 结果参与 `Inline`

### 8.4 错误路径

- 非法模板占位符
- 超出参数范围的占位符
- 真实标识符与保留前缀冲突

## 9. 当前落地检查点

当前实现已经按这条路线落地，复核时应确认：

1. 模板缓存与实例化组件仍然存在且工作正常
2. `GetWhiteListExpression` 继续走 AST 模板消费，不回退到旧的字符串替换逻辑
3. 现有 `Inline` 模板声明方式保持不变
4. 结构敏感测试持续覆盖对象字面量、逗号表达式、tuple 等输入
5. 不适合 `Inline` 的条目继续迁移到 `Op.Compile` 或 `Import`

## 10. 复核清单

1. 模板是否只 parse 一次
2. 调用阶段是否完全避免字符串替换
3. 参数是否始终以 AST 节点参与替换
4. 是否定义了保留占位符命名规则
5. 是否明确了 `Inline` 和 `Compile` 的边界
6. 是否补了结构敏感测试和错误路径测试
