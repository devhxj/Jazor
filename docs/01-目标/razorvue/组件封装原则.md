# RazorVue 组件封装原则

> Status: active
> Scope: `ECMAScript.VueContract`、组件库 binding 与 RazorVue lowering。

## 目标

组件库的 C# API 必须优先使用标准 C# 和 Razor 语义，而不是在其上另建 Vue DSL。
Authoring 时首先使用 `[Parameter]`、`EventCallback`、`RenderFragment`、`record`、原生 `union`、集合初始化器和 C# 命名约定。元数据仅在 C# 不能忠实表达 Vue 合同时存在；异常 JavaScript 名称统一使用成员级 `[ECMAScriptName]`，`[Description("@#...")]` 作为通用兼容形式。

## 最小合同

| 需求 | 默认 C# 表达 | 允许的例外元数据 |
| --- | --- | --- |
| 组件 prop | `[Parameter]` 属性，PascalCase 转 lower camel case | 在属性上用 `[ECMAScriptName("class")]` 等通用名称映射 |
| 普通事件 | `EventCallback` / `EventCallback<T>`，`OnClick` 转 `onClick` | 在属性上用 `[ECMAScriptName("onClick:close")]` 等 listener 名称 |
| 双向绑定 | `Value` + `ValueChanged`、`ModelValue` + `ModelValueChanged`或 `X` + `XChanged` | 仅在 Vue 属性名与 C# 属性名无法对应时显式覆盖 |
| 默认 slot | `ChildContent` / `DefaultContent : RenderFragment` | 无 |
| 普通 slot | `XContent : RenderFragment` 转 `x`；其余 PascalCase 参数名转 kebab-case | 在属性上用 `[ECMAScriptName("header.data-table-select")]` 等 slot 名称 |
| 对象值 | `record` | 无，结构化 record 在 JS 中擦除为对象 |
| 多分支值 | 原生 `union` | 分支类型可赋值重叠且必须保留精确 `AsX` 语义时使用 tagged fallback |
| 未建模 prop | `AdditionalAttributes` | 此是唯一公开 `object?` sink，不能借此弱化已知的强类型 API |
| npm 导入 | 无 C# 等价语法 | 类级导入标识，同时提供 specifier 与 export 名 |

## 当前审计

2026-08-05 初始审计：114 个组件、2478 个 `[Parameter]`、111 个手写 `IUnion`、2 个原生 `union`、245 个 `From(...)` 工厂。组件层上还有 57 条 `VueProp`、141 条 `VueLibraryEmit`、300 条 `VueSlot`，以及每个组件重复的 style/plugin 声明。

本轮收缩后，Vuetify 与 TDesign 的 `VueProp`、`VueSlot` 声明均已归零：异常 prop、dot/camelCase slot 已迁移到成员级通用命名；Vuetify 尚保留 20 条异常 `VueLibraryEmit` 兼容声明。普通 `XChanged`、`OnX`、`ChildContent` / `DefaultContent`、`XContent` 与 PascalCase slot 均由 lowering 约定推断。

当前 union 清点：84 个 tagged fallback、29 个原生 `union`、192 个 `From(...)` 工厂。每次迁移都必须先证明分支两两不可赋值，并以 `AsX` 投影和现有便捷转换回归守护。

| 现有特性 / 类型 | 生产 consumer | 结论 |
| --- | --- | --- |
| `VueLibraryComponent` | analyzer 组件识别、RazorVue named import lowering | 保留：C# 无法表达 npm specifier / named export |
| `ECMAScriptName` / `Description("@#...")` | compiler 与 RazorVue 成员名称映射 | 保留：这是绑定具体 Roslyn 符号的通用命名机制，适用于异常 prop、listener 与 slot 名称 |
| `VueProp.Name` | RazorVue 迁移兼容读取 | 退役：不能精确绑定 `new` 隐藏成员，迁移到成员级通用名称后删除 |
| `VueLibraryEmit.Name` | RazorVue listener 迁移兼容读取 | 收缩为兼容层；`XChanged` / `OnX` 或成员级通用名称是主合同 |
| `VueSlot.Name` / `IsDefault` | RazorVue 迁移兼容读取 | 退役：默认、普通及点号 slot 均可由参数类型、约定和成员级通用名称表达 |
| `VueLibraryStyle` / `VueLibraryPluginRequirement` | 无生产代码 consumer | 退役：不以没有降级语义的重复 attribute 表示应用 bootstrap |
| `VuePropKind`、`AcceptsBinding`、`Required`、`DefaultExpression` | 无生产代码 consumer | Vuetify 已不使用；待 ElementPlus/TDesign 迁移后从共享 contract 删除。Razor SG 负责已知 parameter 与 bind 语法验证 |
| `VueEmitKind`、`PayloadTypeName` | 无生产代码 consumer | Vuetify 已不使用；待 ElementPlus/TDesign 迁移后从共享 contract 删除。`EventCallback<T>` 即是 payload 合同 |
| `VueSlot.Required`、`NamePattern`、`ContextTypeName`、`ContextParameterName` | 无生产 lowering consumer | 退役：类型化 `RenderFragment<T>` 即是 slot context 合同 |
| `IVueLibraryComponent`、`VueLibraryComponentFlags` | 无生产 lowering/analyzer consumer | 标记待删除；类级 import 标识是唯一权威 |

## 迁移顺序

1. 已完成：删除无 consumer 的 style/plugin 声明和相关断言。
2. 已完成：在 library component lowering 中增加无 attribute 的 `X` + `XChanged` model 约定，并以官方 Razor SG 用例回归。
3. 已完成：删除常规 model emit，并将普通事件改为 `OnX`；仅保留异常 Vue 名称。
4. 已完成：删除默认、`XContent` 与 PascalCase/kebab-case slot 声明；`NamePattern` 因无产物 consumer 一并移除。
5. 进行中：RazorVue 已以有效 `[Parameter]` 符号及成员级通用名称为主合同，Vuetify 与 TDesign 手写绑定迁移已完成；迁移 ElementPlus 生成源后删除 `VueProp` / `VueSlot` 兼容表面。
6. 进行中：按分支可赋值关系将手写 `IUnion` 分为 native union、tagged fallback 和直接数组/record 三类，再移除无意义 `From(...)` 工厂。

## 不变约束

- 生产输入仍是官方 Razor SG 生成 C#；不回退到自定义 Razor 解析或 wrapper-JS 协议。
- 名称推断必须由 Roslyn 已绑定的 `[Parameter]` 属性和 `EventCallback` 类型决定，不依赖字符串猜测。
- 异常 Vue 名称和点号 slot 必须绑定到具体成员符号并有可测试的通用元数据路径；动态 slot 必须同时具备强类型 C# API 与产物 lowering，不能只保留声明。
- 不为兼容旧 DSL 增加新的 compiler feature；已退役的公开表面在迁移后视为完全移除。
