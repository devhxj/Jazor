# 文档规范

> 面向：维护仓库文档的贡献者。

## 信息架构

| 目录 | 内容 |
| --- | --- |
| `01-overview/` | 产品定位、范围和系统全景 |
| `02-architecture/` | 当前架构、模块职责和稳定边界 |
| `03-guides/` | 使用、配置、开发、测试和维护流程 |
| `04-roadmap/` | 当前工作方向与状态说明 |
| `05-history/` | 已退役路线和精炼后的演进背景 |

一个事实只保留一个权威位置。根首页可以承担产品定位与阅读起点，目录入口页只做阅读导航；项目内部的 API 和实现细节优先放在源码旁 README；仓库级文档只解释跨项目关系、稳定契约和使用路径。

## 命名与语言

- 目录和普通 Markdown 文件名使用小写 `kebab-case` 英文，例如 `installation-and-configuration.md`。目录入口的 `README.md`、根目录 `CHANGELOG.md` 以及已有语言入口 `README_CN.md` 是约定俗成的例外。
- 正文以中文为主；项目名、类型名、命令、路径、API 和需要保留原文的技术术语使用英文与反引号。
- 标题使用简洁中文，不混用无意义的 title case、全英文标题或日期后缀。
- 使用相对 Markdown 链接；链接指向仓库内稳定文档。

## 结构与表达

长期文档优先采用“定位/范围 -> 设计或流程 -> 边界 -> 相关入口”的结构。需要生命周期说明时，可在标题后使用简短引文标明适用范围；稳定文档聚焦可复现的契约与入口。

面向读者的文字采用正式、清朗且便于朗读的表达：先给出结论，再解释理由；一段展开一个中心判断；长句承载必要的技术关系；并列信息使用对称结构呈现。首段建立阅读节奏，并直接陈述范围、前提和结论。术语采用精准的书面技术表达。句式使用直接主谓宾结构，边界以事实、适用条件、责任归属和诊断结果说明。

段落以单行书写，使源码与渲染保持一致。中文标点统一使用全角，引用中文短语使用全角引号。表格用于稳定的职责、配置或映射对照；代码块提供可复制的最小示例。入口页聚焦阅读路径、权威入口和可复现结论。

## 当前、计划与历史

- 当前架构事实必须能由源码、测试或可复现命令支持。
- 路线图只保留当前状态和已接受的下一阶段优先级。计划必须有明确目标、依赖、owner 和验收标准；完成后，稳定结论收敛到当前状态、架构或指南，不保留过程清单。
- 历史探索、退役路线、旧审计和旧测试快照只保留在 `05-history/` 的精炼说明中。详细旧材料由 Git 历史承担追溯责任。
- 版本演进统一记录在仓库根目录 `CHANGELOG.md`，不在产品或架构文档中重复。

## 更新检查

提交前确认：目录和文件名符合命名规则；链接指向现有权威文档；新内容归入相应权威位置；涉及公共行为的改动已同步到相应架构或使用指南；`git diff --check` 通过。

## ECMAScript 与绑定库 API 注释

所有公开的 ECMAScript 基础类型、Web IDL 类型以及 Vue、Pinia、Vue Router、DateFns、VueUse、Floating UI、VeeValidate、VueI18n、Vue Query、Element Plus、Vuetify、TDesign、Style、Vu Icons、Vue Data UI 和 Devtools 绑定都必须生成 XML 文档。绑定库优先保留对应上游版本的原始 JSDoc、web-types 或 MDN 说明；只有在 C# 投影、联合类型、集合构造器和事件回调等桥接处补充本地说明。补充内容应解释 C# 用法与 JavaScript 行为之间的关系，不能用空泛摘要覆盖上游语义。

绑定文档快照必须记录来源仓库、版本、许可证和采集日期。生成器将 XML 随程序集和 NuGet 包交付，维护者可在仓库根目录运行以下门禁，检查公开声明、枚举值、XML 条目、上游快照和 nuspec 文件是否一致：

```bash
dotnet run --file scripts/csharp/verify-binding-documentation.cs -- --no-build --baseline HEAD
```

Web IDL 文档来源使用 MDN 快照，许可证为 `CC-BY-SA-2.5`；Vue 生态绑定使用各上游项目锁定版本的文档快照。修改绑定声明或生成器后，应同时更新快照、生成输出和 XML，并运行对应生成器的 `documentation --check`。
