# 发布说明规范

本规范定义 `CHANGELOG.md` 的未发布条目和 GitHub Release 正文格式。发布说明面向使用者，说明升级后能做什么、行为如何变化，以及是否需要迁移。

## 固定结构

每个版本使用一个日期和一个版本标题：

```md
## 2026-09-09

### Jazor 0.33.0

中文 | English

#### 新增功能

- 中文条目。by @github-user

#### 体验优化

- 中文条目。by @github-user

#### 问题修复

- 中文条目。by @github-user

#### 其他变更

- 中文条目。by @github-user

New Features

- English entry. by @github-user

Improvements

- English entry. by @github-user

Bug Fixes

- English entry. by @github-user

Chores

- English entry. by @github-user
```

正式版本只保留实际存在的分类。中英文分类和条目顺序必须一一对应；英文不是逐字翻译要求，但必须表达相同的用户可观察行为、范围和迁移影响。

未发布内容使用最新日期下的 `### 未发布 | Unreleased` 标题，并沿用同一套双语分类。确定版本号和发布日期后，将该标题替换为 `### Jazor x.y.z`，再移动到正式日期；不要在正式版本中保留“未发布”字样。

## 分类规则

| 中文 | English | 放入内容 |
| --- | --- | --- |
| 新增功能 | New Features | 新能力、新支持面、新公共 API 或新包 |
| 体验优化 | Improvements | 现有能力的可见改进、性能、诊断和工作流改善 |
| 问题修复 | Bug Fixes | 对已发布行为的错误修正、回归修复和兼容性修复 |
| 其他变更 | Chores | 构建、测试、依赖、发布基础设施和维护性变更 |

分类按上表顺序书写。测试或文档若改变了用户可见的工作流，归入 `Improvements`；仅用于内部验证的内容归入 `Chores`。同一变更只出现一次，不要在多个分类重复描述。

## 条目写法

- 先写结果，再写范围或限制。使用“现在可以……”“修复……”“发布时会……”等面向使用者的动词。
- 写出触发条件和可观察结果；不要写类名、文件路径、内部重构过程或测试流水账，除非它们是用户需要迁移的公共 API。
- 一个条目只表达一个主题。相关的多个提交可以合并成一个条目，但不要把互不相关的修复串在同一句中。
- 明确限制和迁移路径。删除、重命名、默认值变化、格式升级或不兼容行为必须说明旧写法、新写法和是否支持降级。
- 每条末尾使用 `by @github-user` 署名。署名取实际贡献者的 GitHub 用户名；多人共同完成时可写 `by @user1, @user2`。没有可确认的贡献者时，不猜测用户名，先补齐来源再发布。
- 不在条目中写版本号、发布日期或比较链接；这些由章节标题和发布脚本负责。

## 编写流程

1. 在最新日期下维护 `### 未发布 | Unreleased`，按四个分类持续追加条目。
2. 合并前检查每条是否面向用户、是否有对应的实现或验证证据、是否已署名；内部细节留在提交记录或 PR 中。
3. 确定版本通道后，将未发布章节改为 `### Jazor x.y.z`，确认日期、分类、中英文条目和迁移说明完整。
4. 运行 `dotnet run --file scripts/csharp/release-notes.cs -- --tag vX.Y.Z --repository devhxj/Jazor`，确认输出只包含该版本章节。
5. 按[发版与版本规则](./release-and-versioning.md)执行质量门禁、消费者验证、打 tag 和推送。GitHub Actions 会把对应版本章节作为 Release 正文，并在末尾追加比较链接。

## 检查清单

- [ ] 章节位于最新日期下，标题为 `### Jazor x.y.z` 或 `### 未发布 | Unreleased`。
- [ ] 中英文标题存在，分类顺序一致，只保留有内容的分类。
- [ ] 中英文条目一一对应，描述的是用户可观察行为。
- [ ] 每条都有可确认的 `by @github-user` 署名。
- [ ] 破坏性变更、格式变化和弃用行为写明迁移路径。
- [ ] 未写入文件路径、内部实现流水账或无法验证的性能数字。
- [ ] 发布脚本输出对应版本章节，未混入其他版本或未发布内容。
- [ ] GitHub Release 正文包含版本说明和 compare 链接。

## 与历史版本的关系

已发布章节只做勘误追加，不重排、不改写既有事实。历史章节可能使用早期分类或单语格式；本规范从采用之日起约束新的未发布条目和后续版本，不要求重写历史记录。
