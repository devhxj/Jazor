# RazorVue Playground 支持缺口状态（2026-05-26）

本文只记录当前仍不支持、仍需保守 fail-fast、或仍需产品化补齐的 RazorVue / Playground 能力边界。历史过程、阶段流水账和已完成细节不放在本文中，必要时通过 git 历史追溯。

## 边界规则

- RazorVue 的主输出合同是最终 `.vue` / render-function artifact，不是 wrapper-JS 中间协议。
- C# 表达式、成员、类型引用、CLR helper、import/reference 语义必须继续走 `Jazor.Compiler` / `SemanticWalker`。RazorVue 只负责 Vue artifact framing、Razor frontend 还原和组件/slot 描述符桥接。
- RazorVue 的 `.razor` 输入必须保持官方 Razor Source Generator 可编译；不能引入只有 RazorVue 自己懂、但官方 `.razor.g.cs` 无法绑定的参数或类型形态。
- 不确定能否保持求值顺序、副作用次数、slot/component metadata、HMR identity 或 Vue runtime 语义时，继续显式 fail-fast。

## 当前仍不支持

### 1. Render / Template

- `imperative body -> canonical <template>` 回流仍不支持。render tree 任意位置包含 imperative node 时，SFC 输出统一切到 render-function `.vue`，不会尝试把 mixed imperative subtree 还原成 canonical template subtree。
- 真正 async render contract 不支持。`await`、`await foreach`、`await using`、`await using var` 在 render path 中继续显式失败，不生成 fire-and-forget async render。
- `goto` 不支持。当前 `Jazor.Compiler` 没有等价 JS lowering，RazorVue 不会静默擦除跳转语义。
- 声明式 count-style `for` 只接受可归一到 `__jazorVueForRange(...)` 的单 iterator 形态。多 iterator、非加减式 iterator、`i = Next(i)`、`i = i * step`、逐轮动态步进协议不作为声明式 `RazorVueForNode` 支持；如果代码能由同步 imperative render 主线诚实承载，则走 render-function，否则失败。

### 2. Template Code Block / Markup

- 声明式模板 code-block 不是通用语句执行模型。除带 initializer 的 template local、同一线性局部声明前缀内一次简单赋值、以及已定义的结构化控制语句外，任意赋值、递增/递减、delegate/callable template state 不会被塞进 canonical template node。
- 动态 raw markup 不支持。`AddMarkupContent(...)`、`AddContent(..., MarkupString)` 和 Razor template 中的 `MarkupString` 只接受源码可分析且可证明为静态 HTML 的子集；运行时拼接 markup、运行时构造 `MarkupString`、脚本/raw HTML 执行语义继续失败。
- 后续可观察写入的 `RenderFragment` / `MarkupString` / static-markup carrier 不支持；普通 setup `let` carrier 支持不会放宽这些 source-stable 合同。

### 3. Component / `System.Type`

- 动态 `System.Type` 组件不支持。当前只支持可源码证明最终等于 `typeof(IVueComponent)` 的静态目标，包括 direct `typeof(...)`、source-stable local carrier、source-stable current-component member carrier 和受控只读转发链。
- `System.Type` carrier 后续可观察写入、运行时 `Type` dataflow、非组件 `typeof(...)` 作为组件目标继续失败。
- 组件 `System.Type` carrier 只能作为 `OpenComponent(Type)` 的静态组件目标使用，不能当普通 render content、attribute、key、condition 或 loop source。
- 普通 CLR/type-token 表达式仍归 `Jazor.Compiler` / `SemanticWalker` 处理，例如 `typeof(TestDisposable).Name`；RazorVue 不提供另一套 type-token lowering。

### 4. Fragment / Slot Carrier

- 任意 `RenderFragment` / delegate dataflow 不支持。只接受 inline template、source-stable local/member carrier、受支持 current-component/local function fragment factory 这类可静态追踪形态。
- recursive fragment factory、无法静态还原匿名模板 body 的 callable、需要任意 getter/dataflow 推理的 fragment member carrier 不支持。
- fragment factory 的 `ref` / `out` 参数和 by-reference 转发/逃逸不支持。`in` 只读值参数已支持按 captured value 读取，但继续传入任意 `ref` / `out` / `in` by-reference invocation 会显式失败。

### 5. Render Helper / Open Frame

- render helper 的 `ref` / `out` 参数不支持；`RenderTreeBuilder` 参数也必须保持普通 by-value。非 builder 的 `in` 只读值参数已支持源码可分析读取，但把 `in` 参数继续转发到任意 by-reference invocation、写回协议或逃逸协议仍会显式失败。
- recursive render helper 不支持。
- caller-owned open frame helper 只支持受控 replay：attribute/key/spread mutation、slot/default-slot assignment、ambient child emission、helper-local 平衡 `OpenRegion` / `CloseRegion`。跨 helper 留下未闭合 frame、关闭/重开 caller-owned frame、改变最终 active frame、region 逃逸/不平衡、需要跨 helper 推断 frame shape 的协议继续失败。
- 同文件 helper class lowering 只接受同步、源码可分析、同 artifact module 内 runtime class。泛型 helper class、record、helper component、ECMAScript host type 不会被该通道扁平化；普通模块级 static nested class 导出策略仍保持 fail-fast。

### 6. Setup / Lifecycle / Render Control

- setup/lifecycle lowering 不是通用执行模型。`async` helper、`Task` / `ValueTask` 返回 helper、`ref` / `out` 参数、一般外部 invocation、未知实例 method-call payload、超出当前 `SemanticWalker` statement lowering 支持面的 helper body 继续失败。
- `SetParametersAsync` 只支持 no-op、直达 `ComponentBase.SetParametersAsync(...)` 的 pass-through、以及受控 base-pass-through 后的 source-stable local / local function / callable local 前缀、线性有序 `InvokeAsync(...)` emit 序列、受控 `if` / `else` emit 分支、受控 guard-return / `if/else` 单分支 `return` emit 分支、terminal-only guard-return / `if/else` 双分支 `return` no-op、emit 后 terminal `if/else` 双分支 `return`、受控传统 `switch` emit 分支、受控 `try/finally` emit cleanup、受控 `try/catch` emit recovery 与受控 `try/catch/finally` emit recovery+cleanup（含 no-op `try` cleanup-only、no-op `catch` recovery、no-op try+catch cleanup-only finally、try body 顶层裸 `return;` + catch recovery / finally cleanup、no-op `finally` cleanup 与受控 guard-return 内嵌组合）；base pass-through 后的可达无操作 `return;` 会终止序列，后续不可达 emit / mutation 不会被 replay 成 lifecycle 行为。额外 mutation、非 emit loop / pattern switch 控制流、任意外部 invocation 或更一般方法体不支持。
- `ShouldRender` 只支持已定义的 no-op / base pass-through / 单表达式 / switch expression / 线性局部前缀 / 局部函数 / 受控 local lambda delegate / 受控 method-group delegate carrier / 受控 `if` / 受控传统 `switch` / guarded pattern `switch`（含受控 block / `if` / loop / `try/catch/finally` 内嵌套形态）/ 受控 `while` / `do-while` / `for` / 同步 `foreach` / 受控同步 `try/catch/finally` / 受控同步异常分支 / 受控声明 local 形态。`await foreach`、纯 `throw` 且无正常 `return bool` 路径、表达式内部 mutation、current-component property/field mutation、任意外部/member mutation、任意 invocation expression statement、除“声明点直接初始化为同步匿名函数或受控 method group、返回 `bool` 并仅作为直接调用目标使用”以外的局部 lambda/delegate state、delegate 重赋值、delegate 值比较/传参/返回、嵌套局部函数、外部引用程序集无源码 base override 仍保守 `FullReloadRequired` 或 fail-fast。
- base pass-through 若最终落到外部引用程序集里的无源码 override，继续显式失败，不乐观当成 no-op。

### 7. DOM Event / Route / Consumer Build

- 任意 `on*` 字符串 attribute 不会被当成 DOM event。当前需要 event callback/delegate-like value 或 Razor/RenderTree event modifier metadata。
- component emit modifier 不与 HTML DOM event modifier 共用路径。组件 emits 继续按 descriptor-aware component event lowering 处理。
- `.vue` default export/import 不是 Jazor authored module 的编译器边界。需要通过 `razorvue-sfc-bridge` 把 SFC default component 转成 named export/import；不计划在 Jazor 编译器里放开 default export/import。
- RazorVue library mode 仍需要 consumer 构建层。Playground 的 colocated `consumer` 是单 ASP.NET Core 项目里的前端消费构建层，不是第二个 runtime host；标准 ASP.NET Core + RazorVue library-mode 模板和约定仍需继续产品化。
- route template -> Vue Router bridge 仍拒绝无法诚实映射的长尾形态：optional separator 参数不是 segment 尾部、没有紧邻前置 optional separator、需要多层组合展开的 composite/mixed segment，以及无法转换成“一个 Vue Router path regex + generated metadata 二次校验”的 constraint 组合。未知自定义 constraint、当前 ASP.NET Core 默认 `ConstraintMap` 不内置的 `date` 仍保持 fail-fast。

## 已从缺口移除

- Body-level imperative render 主线已覆盖 `return`、`while` / `do-while`、带 `break` / `continue` 的 `for` / `foreach`、`switch`、`lock`、`try/catch/finally`、`using` / `using declaration`、无 `goto` labeled statement、局部 mutation、静态 markup / `MarkupString`。
- Imperative `AddComponentParameter(...)` 已按 descriptor 区分 prop / emit / slot；current-component slot forwarding、builder-style `RenderFragment` / `RenderFragment<T>` slot callback、nested component metadata/import 已进入正式路径。
- 静态 `OpenComponent(Type)` 及 source-stable local/current-component member `System.Type` carrier 已支持；这不是动态组件支持。
- Razor IR mixed attribute、lowercase `class` / `style` fallthrough、DOM event modifier、static markup、typed/untyped `RenderFragment` carrier、fragment factory、template local、setup/lifecycle helper 受控 payload、动态 `ShouldRender` cached render gate 已进入支持面。
- Runtime naming contract 已收敛：C# authoring surface 继续使用 `PascalCase`，Vue runtime/template 边界统一输出 `camelCase`，例如 `props.modelValue`、`item.title`、`item.isDone`。
- 本轮补齐 `ShouldRender` 的 switch expression 与 guarded pattern `switch` cached render gate；非穷尽 guarded pattern `switch` 通过 fallthrough sentinel 保留未命中 / `break` 后继续执行 trailing `return` 的语义，连续 guarded pattern `switch`、前置局部声明、以及受控 block / `if` / loop / `try/catch/finally` 内嵌套 guarded pattern `switch` 均已覆盖。guard/pattern 仍禁止 mutation / lambda / local-function，超出受控语句子集的方法体继续 fail-fast，避免错误吞掉后续 `return` 语义。
- 本轮继续补齐 `ShouldRender` 嵌套 guarded pattern `switch`：RazorVue 仍复用 `SemanticWalker` 生成的 pattern-switch IIFE，不手写 pattern/member 语义；仅在 RazorVue gate 边界递归识别 compiler-owned IIFE，并用唯一 fallthrough sentinel 把 case `return bool` 接回外层 `ShouldRender`，同时让未命中 / `break` 继续执行外层后续语句。
- 本轮继续补齐 `ShouldRender` 受控 loop cached render gate：同步 `while` / `do-while` / `for` / `foreach` 可包含局部声明、local-only mutation、受控 `if` / 传统 `switch`、`return bool`，并在 loop scope 内保留 `break` / `continue` 语义；`for` header 同样只允许局部声明与 local-only mutation，`foreach` collection 表达式仍禁止 mutation / lambda / local-function。`await foreach`、current-component property/field mutation、任意外部/member mutation 与任意 invocation expression statement 仍不放开。
- 本轮继续补齐 `ShouldRender` 受控同步 `try/catch/finally` cached render gate：`try` / `catch` / `finally` body 复用同一受控语句子集，可包含局部声明、local-only mutation、受控 `if` / 传统 `switch` / loop 与 `return bool`；catch filter 仍禁止 mutation / lambda / local-function，catch 参数会通过 compiler host seam 稳定 alias，源码名即使是 `props` 等 setup/gate 保留名也不会遮蔽运行时 binding，最终发射继续走 `SemanticWalker` 的真实 `try/catch/finally` lowering。async try 相关形态、current-component property/field mutation、任意外部/member mutation 与无法证明正常路径返回 bool 的形态仍不放开。
- 本轮继续补齐 `ShouldRender` reserved catch binding：`catch (Exception props)` 这类源码名会映射为 `__jazorShouldRenderLocal...` catch 参数，catch filter、handler 内引用和裸 `throw;` 共享同一别名；普通局部、pattern local 与 catch 参数现在共用同一 `ShouldRender` alias contract，避免 setup `props` / gate cache 变量被遮蔽。
- 本轮继续补齐 `ShouldRender` 受控同步异常分支：`throw new ...` 可出现在受控语句子集内并按 `SemanticWalker` 发射为真实 JavaScript `throw`，但方法体仍必须存在可证明的正常 `return bool` 路径；纯 `throw` / 只有异常终止路径的 `ShouldRender` 继续 `FullReloadRequired`，并且 `finally` 中的终止 `throw` 不会被前面的 `return bool` 掩盖成正常 gate，避免把无正常布尔结果的方法误包成 cached render gate。
- 本轮继续补齐 `SetParametersAsync` base-pass-through 后的可达无操作 `return;` 终止语义：`await base.SetParametersAsync(parameters); return;` 后的不可达 emit / mutation 不再让 analyzer 报 `JAZORVUE006`，也不会生成 Vue `watch` 或把 HMR 边界提升为 `FullReloadRequired`。这不是一般控制流支持，只有可达前缀仍满足现有 base-pass-through / 线性 emit 子集时才接受。
- 本轮继续补齐 `SetParametersAsync` 受控条件 emit：`await base.SetParametersAsync(parameters); if (Value > 0) { await ValueChanged.InvokeAsync(Value); } else { await ReadyChanged.InvokeAsync(false); }` 这类条件和分支 payload 仍经 `RazorVueExpressionEmitter` / `SemanticWalker` lowering，可包含 source-stable local 条件并在 watch body 中按 C# 顺序物化一次。条件/分支内 mutation、非 emit 语句、任意外部 invocation、带 `return` 的分支和更一般控制流仍保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控传统 `switch` emit：`await base.SetParametersAsync(parameters); switch (Value) { case 0: await ReadyChanged.InvokeAsync(false); break; default: await ReadyChanged.InvokeAsync(Value > 0); break; }` 会 lower 到同一个 immediate Vue `watch` 里的 JavaScript `switch`。switch value、case label 和 emit payload 仍经 `RazorVueExpressionEmitter` / `SemanticWalker` lowering；每个 section 必须包含 constant/default label、受控 emit/no-op body，并以 terminal `break` 结束。pattern/guarded switch、fallthrough 空 section、section 内 mutation / `return` / 任意外部 invocation、loop / try 等更宽控制流继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/finally` emit cleanup：`await base.SetParametersAsync(parameters); var ready = Value > 0; try { await ValueChanged.InvokeAsync(Value); } finally { await ReadyChanged.InvokeAsync(ready); }` 会 lower 到同一个 immediate Vue `watch` 里的真实 JavaScript `try/finally`。try 前置 source-stable local 会在进入 `try` 前按源码顺序物化一次；`try` / `finally` body 复用受控 emit/no-op/`if`/传统 `switch` 子集，try body 顶层裸 `return;` 在存在 finally cleanup emit 时会保留为真实 JS `return;` 并先执行 pending local prelude。`catch`、`throw`、带值 `return`、finally 内 `return`、mutation、loop、pattern switch、外部 invocation 和任何需要异常语义重构的更宽控制流继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 guard-return emit：`await base.SetParametersAsync(parameters); var ready = Value > 0; if (!ready) { return; } await ValueChanged.InvokeAsync(Value);` 会 lower 到同一个 immediate Vue `watch` 里的 JavaScript `return;` guard。guard condition 和后续 emit payload 仍经 `RazorVueExpressionEmitter` / `SemanticWalker` lowering，condition 依赖的 source-stable local 会在 guard 前按源码顺序物化一次。当前 emit 形态只接受无 `else`、单个空 `return;` guard 且后续仍存在受控 emit 行为；terminal-only guard-return 已作为 no-op 终止形态单独支持。带值 `return`、mutation、loop、catch、pattern switch、外部 invocation 和任何需要一般 CFG 重构的更宽控制流继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 `if/else` 单分支 `return` emit：`if (!ready) { return; } else { await ValueChanged.InvokeAsync(Value); }` 和 `if (ready) { await ValueChanged.InvokeAsync(Value); } else { return; }` 会 lower 到同一个 immediate Vue `watch` 里的真实 JavaScript `if/else`，并保留 `return;` 分支的短路语义。emit 形态只有 exactly-one-branch 空 `return;`、另一分支仍落在受控 emit/no-op/`if`/传统 `switch`/`try-finally` 子集内时才接受；双分支 `return` 若没有可达 runtime 行为已作为 no-op 终止形态单独支持。带值 `return`、return 分支后继续拼接不可证明顺序、mutation、loop、catch、pattern switch、外部 invocation 和一般 CFG 重构继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/catch` emit recovery：`try { await ValueChanged.InvokeAsync(Value); } catch (Exception) { await ReadyChanged.InvokeAsync(false); }` 和 `catch { ... }` 会 lower 到同一个 immediate Vue `watch` 里的真实 JavaScript `try/catch`。当前只接受单个 catch-all / `System.Exception` catch；`catch (Exception error)` 这类声明但不使用的 catch binding 会按 JS `catch { ... }` 发射，不暴露 exception object。`catch (Exception) when (ready)` 这类不引用 catch 变量且 filter 落在 lifecycle payload 安全子集内的形态会发射为 JS catch filter gate，filter 为 false 或 filter 自身抛错时重抛原异常。`try` / `catch` body 复用受控 emit/no-op/`if`/传统 `switch`/guard-return/`try-finally` 子集；typed catch 分派、多 catch、catch 变量 payload、filter 内 mutation / lambda / local-function、`throw` / `return`、mutation、loop、pattern switch、外部 invocation 和需要 CLR exception typing 的更宽控制流继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/catch/finally` emit recovery+cleanup：`try { await ValueChanged.InvokeAsync(Value); } catch (Exception) { await ReadyChanged.InvokeAsync(false); } finally { await ReadyChanged.InvokeAsync(ready); }` 会 lower 到同一个 immediate Vue `watch` 里的真实 JavaScript `try/catch/finally`。`try` 前置 source-stable local 仍在进入 `try` 前按源码顺序物化一次；`try` / `catch` / `finally` body 复用受控 lifecycle statement 子集，未使用的 `System.Exception` catch binding 同样不会进入 JS 输出合同，catch filter 使用同一 gate/rethrow 合同。typed catch 分派、多 catch、catch 变量 payload、filter 内 mutation / lambda / local-function、`throw` / `return`、mutation、loop、pattern switch、外部 invocation 和一般 CFG / CLR exception typing 重构继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/finally` 内嵌 guard-return cleanup：`try { if (!ready) { return; } await ValueChanged.InvokeAsync(Value); } finally { await ReadyChanged.InvokeAsync(ready); }` 会在同一个 immediate Vue `watch` 里保留 `try` 内短路 `return;` 与 `finally` cleanup 顺序。try body 顶层裸 `return;` + finally cleanup 已作为同一受控 cleanup 形态支持；带值 `return`、catch/finally 内 `return`、双分支 `return`、catch filter、typed catch 分派、多 catch、catch 变量 payload、`throw`、mutation、loop、pattern switch、外部 invocation 和一般 CFG / CLR exception typing 重构继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/catch/finally` 内嵌 guard-return recovery+cleanup：`try { if (!ready) { return; } await ValueChanged.InvokeAsync(Value); } catch (Exception) { await ReadyChanged.InvokeAsync(false); } finally { await ReadyChanged.InvokeAsync(ready); }` 会在同一个 immediate Vue `watch` 里保留 source-stable local 单次物化、`try` 内短路 `return;`、catch recovery 和 finally cleanup 顺序。try body 顶层裸 `return;` + finally cleanup 已作为同一受控 cleanup 形态支持；带值 `return`、catch/finally 内 `return`、catch filter、typed catch 分派、多 catch、catch 变量 payload、`throw`、mutation、loop、pattern switch、外部 invocation 和一般 CFG / CLR exception typing 重构继续保持 unsupported / `FullReloadRequired`。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/catch` / `try/catch/finally` 中声明但不使用的 `System.Exception` catch binding：`catch (Exception error) { await ReadyChanged.InvokeAsync(false); }` 与无变量 catch 一样 lower 为 JS `catch { ... }`，只接受 `error` 未被 filter/body 引用的语法噪声形态。`error is not null` 等 catch 变量 payload 仍保持 unsupported，避免在 RazorVue lifecycle lowering 内引入 CLR exception object 模拟。
- 本轮继续补齐 `SetParametersAsync` 单个 catch-all / `System.Exception` catch filter：`catch (Exception) when (ready) { await ReadyChanged.InvokeAsync(false); }` 会 lower 成 JS `catch (__jazorLifecycleCatch)` 内的 handled gate，filter prelude 与表达式仍经 `RazorVueExpressionEmitter` / `SemanticWalker` lowering。filter 为 false 或 filter 求值抛错时会 `throw __jazorLifecycleCatch;`，不会把未匹配异常吞掉；引用 catch 变量的 filter 仍 unsupported。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/catch/finally` 内嵌 catch filter + guard-return 组合：`try { if (!ready) { return; } await ValueChanged.InvokeAsync(Value); } catch (Exception) when (ready) { await ReadyChanged.InvokeAsync(false); } finally { await ReadyChanged.InvokeAsync(ready); }` 复用同一 immediate Vue `watch`，并保留 source-stable local 单次物化、try 内短路、filter gate/rethrow、catch recovery 与 finally cleanup 顺序。
- 本轮继续补齐 `SetParametersAsync` 受控 `try/catch/finally` 中 no-op `finally` cleanup：`finally { }`、`finally { await Task.CompletedTask; }` 或等价 no-op lifecycle statement 会保留真实 JS `finally {}` 边界但不生成额外 emit payload，catch recovery 仍生成同一个 immediate Vue `watch`。finally 内 mutation、throw、`return`、loop、pattern switch、外部 invocation 和一般 CFG / CLR exception typing 重构继续保持 unsupported / `FullReloadRequired`。
