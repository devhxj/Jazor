# RazorVue Playground 支持缺口状态（2026-05-28）

本文只记录当前仍不支持、仍需保守 fail-fast、或仍需产品化补齐的 RazorVue / Playground 能力边界。历史过程、阶段流水账和已完成细节不放在本文中，必要时通过 git 历史追溯。

## 边界规则

- RazorVue 的主输出合同是最终 `.vue` / render-function artifact，不是 wrapper-JS 中间协议。
- C# 表达式、成员、类型引用、CLR helper、import/reference 语义必须继续走 `Jazor.Compiler` / `SemanticWalker`。RazorVue 只负责 Vue artifact framing、Razor frontend 还原和组件/slot 描述符桥接。
- RazorVue 的 `.razor` 输入必须保持官方 Razor Source Generator 可编译；不能引入只有 RazorVue 自己懂、但官方 `.razor.g.cs` 无法绑定的参数或类型形态。
- 不确定能否保持求值顺序、副作用次数、slot/component metadata、HMR identity 或 Vue runtime 语义时，继续显式 fail-fast。

## 当前仍不支持

### 1. Render / Template

- 通用 `imperative body -> canonical <template>` 回流仍不支持。除已完成的 root-only simple constant / guarded non-declaration pattern `switch`（含合法空 case 分组）、root-level terminal guard-return / `if/else` 单分支裸 `return;`、受控 nested guard-return 单分支裸 `return;`、root-level `try/finally` 空 cleanup、root-level `try/finally` 纯静态 try body + 纯静态 cleanup 输出恢复子集、root-level catch-all 空 recovery 及二者组合、root-level `lock(this)` 可擦除同步壳、root-level no-op labeled block、root-level null/default `using` statement、root-level `do { ... } while(false)` 单次执行恢复子集、root-level `while(false)` 静态零次执行恢复子集外，render tree 任意位置包含 imperative node 时仍会保守切到 render-function `.vue`；mixed imperative subtree、需要跨分支复制 tail 的 nested early return、双分支 return 且无可达 template 输出、`goto case/default` 显式跳转、声明 pattern 绑定局部的 switch、guard/pattern 含副作用或需要单次求值缓存的 switch、真实 catch recovery / catch filter / catch variable payload / throw / runtime-sensitive finally cleanup（动态 try/finally 输出、mutation 或依赖真实异常路径的 cleanup）、非 `this` lock target、真实 disposable resource / `using declaration` / async using、runtime-dependent loop condition / loop body mutation / loop control transfer、同 artifact helper type runtime declaration 需求、mutation、exception/async/byref 语义、动态 raw markup 或无法通过 canonical template 预检的 branch/tail body 不会被强行还原成 template subtree。
- 真正 async render contract 不支持。`await`、`await foreach`、`await using`、`await using var` 在 render path 中继续显式失败，不生成 fire-and-forget async render。
- `goto` 不支持。当前 `Jazor.Compiler` 没有等价 JS lowering，RazorVue 不会静默擦除跳转语义。
- 声明式 count-style `for` 只接受可归一到 `__jazorVueForRange(...)` 的单 iterator 形态。多 iterator、非加减式 iterator、`i = Next(i)`、`i = i * step`、逐轮动态步进协议不作为声明式 `RazorVueForNode` 支持；如果代码能由同步 imperative render 主线诚实承载，则走 render-function，否则失败。

### 2. Template Code Block / Markup

- 声明式模板 code-block 不是通用语句执行模型。除带 initializer 的 template local、同一线性局部声明前缀内一次简单赋值、以及已定义的结构化控制语句外，任意赋值、递增/递减、delegate/callable template state 不会被塞进 canonical template node。
- 动态 raw markup 不支持。`AddMarkupContent(...)`、`AddContent(..., MarkupString)` 和 Razor template 中的 `MarkupString` 只接受源码可分析且可证明为静态 HTML 的子集；运行时拼接 markup、运行时构造 `MarkupString`、脚本/raw HTML 执行语义继续失败。
- 后续可观察写入的 `RenderFragment` / `MarkupString` / static-markup carrier 不支持；普通 setup `let` carrier 支持不会放宽这些 source-stable 合同。

### 3. Component / `System.Type`

- 动态 `System.Type` 组件不支持。当前只支持可源码证明最终等于 `typeof(IVueComponent)` 的静态目标，包括 direct `typeof(...)`、source-stable local carrier、source-stable current-component member carrier 和受控只读转发链。
- `System.Type` carrier 后续可观察写入、运行时 `Type` dataflow、非组件 `typeof(...)` 作为组件目标继续失败。
- 组件 `System.Type` carrier 只能作为 `OpenComponent(Type)` 的静态组件目标使用，不能当普通 render content、attribute、key、condition 或 loop source。
- 普通 CLR/type-token 表达式仍归 `Jazor.Compiler` / `SemanticWalker` 处理，例如 `typeof(TestDisposable).Name`；RazorVue 不提供另一套 type-token lowering。

### 4. Fragment / Slot Carrier

- 任意 `RenderFragment` / delegate dataflow 不支持。只接受 inline template、source-stable local/member carrier、受支持 current-component/local function fragment factory 这类可静态追踪形态。
- recursive fragment factory、无法静态还原匿名模板 body 的 callable、需要任意 getter/dataflow 推理的 fragment member carrier 不支持。
- fragment factory 的 `ref` / `out` 参数和 by-reference 转发/逃逸不支持。`in` 只读值参数已支持按 captured value 读取，但继续传入任意 `ref` / `out` / `in` by-reference invocation 会显式失败。

### 5. Render Helper / Open Frame

- render helper 的 `ref` / `out` 参数不支持；`RenderTreeBuilder` 参数也必须保持普通 by-value。非 builder 的 `in` 只读值参数已支持源码可分析读取，但把 `in` 参数继续转发到任意 by-reference invocation、写回协议或逃逸协议仍会显式失败。
- recursive render helper 不支持。
- caller-owned open frame helper 只支持受控 replay：attribute/key/spread mutation、slot/default-slot assignment、ambient child emission、helper-local 平衡 `OpenRegion` / `CloseRegion`。跨 helper 留下未闭合 frame、关闭/重开 caller-owned frame、改变最终 active frame、region 逃逸/不平衡、需要跨 helper 推断 frame shape 的协议继续失败。
- 同文件 helper class lowering 只接受同步、源码可分析、同 artifact module 内的非泛型非 record runtime class。泛型 helper class、helper component 继续 fail-fast；record / struct / 非组件 ECMAScript host data carrier 仍交给 `Jazor.Compiler` 结构化 lowering 或 host import 语义处理，不进入 runtime helper class 通道；普通模块级 static nested class 导出策略仍保持 fail-fast。

### 6. Setup / Lifecycle / Render Control

- setup/lifecycle lowering 不是通用执行模型。除普通 lifecycle no-op 判定中已支持的当前组件 private 同步 helper 纯返回值形态（无参、所有实参可证明无副作用且形参均为普通按值参数，或受控 `params` 展开，含隐式 params array、显式 array carrier、collection expression carrier 与调用上下文内 params array `Length` / 一维 `GetLength(0)` 只读）外，`async` helper、`Task` / `ValueTask` 返回 helper、`ref` / `out` / `in` 参数、带副作用实参、外部/非 private invocation、未知实例 method-call payload、超出当前 `SemanticWalker` statement lowering 支持面的 helper body 继续失败。
- `SetParametersAsync` 只支持 no-op、直达 `ComponentBase.SetParametersAsync(...)` 的 pass-through、以及受控 base-pass-through 后的 source-stable local / local function / callable local 前缀、线性有序 `InvokeAsync(...)` emit 序列、受控 `if` / `else` emit 分支、受控 guard-return / `if/else` 单分支 `return` emit 分支、terminal-only guard-return / `if/else` 双分支 `return` no-op、emit 后 terminal `if/else` 双分支 `return`、受控传统 `switch` emit 分支、受控 `try/finally` emit cleanup、受控 `try/catch` emit recovery 与受控 `try/catch/finally` emit recovery+cleanup（含 no-op `try` cleanup-only、no-op `catch` recovery、no-op try+catch cleanup-only finally、try body 顶层裸 `return;` + catch recovery / finally cleanup、无 runtime-before-return 的 terminal try/catch no-op、声明但不使用 catch 变量的语法噪声、catch 变量只参与 null/non-null filter、catch body 受控 `if` 条件或 catch body 直接 emit payload 的可证明折叠、no-op `finally` cleanup 与受控 guard-return 内嵌组合）；base pass-through 后的可达无操作 `return;` 会终止序列，后续不可达 emit / mutation 不会被 replay 成 lifecycle 行为。额外 mutation、非 emit loop / pattern switch 控制流、任意外部 invocation、`error.Message` / `GetType()` 等真实 exception payload 读取或更一般方法体不支持。
- `ShouldRender` 只支持已定义的 no-op / base pass-through / 单表达式 / switch expression / 线性局部前缀 / 局部函数 / 受控 local lambda delegate / 受控 method-group delegate carrier / 受控 delegate null-check / 受控 delegate compare / 受控同方法局部函数 delegate 参数/返回流 / 受控 `if` / 受控传统 `switch` / guarded pattern `switch`（含受控 block / `if` / loop / `try/catch/finally` 内嵌套形态）/ 受控 `while` / `do-while` / `for` / 同步 `foreach` / 受控同步 `try/catch/finally` / 受控同步异常分支 / 受控声明 local 形态。`await foreach`、纯 `throw` 且无正常 `return bool` 路径、表达式内部 mutation、current-component property/field mutation、任意外部/member mutation、任意 invocation expression statement、除“声明点直接初始化，或同一线性局部声明前缀内先声明再一次赋值初始化为同步匿名函数或受控 method group、返回 `bool` 并仅作为直接调用目标、null/default 空值判断或受控 delegate compare 使用”以及“声明点直接初始化为 `null` / `default` 并仅作为 null/default 空值判断、或传入同方法局部函数 consumer 后只作 null/default 空值判断使用”以外的局部 lambda/delegate state、null/default 初始化 delegate 调用、delegate 多次重赋值、分支赋值、赋值后逃逸、delegate 参数逃逸、返回非匿名函数 delegate、跨 member / 外部 callable 传参返回、嵌套局部函数、外部引用程序集无源码 base override 仍保守 `FullReloadRequired` 或 fail-fast。
- base pass-through 若最终落到外部引用程序集里的无源码 override，继续显式失败，不乐观当成 no-op。

### 7. DOM Event / Route / Consumer Build

- 任意 `on*` 字符串 attribute 不会被当成 DOM event。当前需要 event callback/delegate-like value 或 Razor/RenderTree event modifier metadata。
- component emit modifier 不与 HTML DOM event modifier 共用路径。组件 emits 继续按 descriptor-aware component event lowering 处理。
- `.vue` default export/import 不是 Jazor authored module 的编译器边界。需要通过 `razorvue-sfc-bridge` 把 SFC default component 转成 named export/import；不计划在 Jazor 编译器里放开 default export/import。
- RazorVue library mode 的最小 colocated consumer build / publish handoff 已有 SDK integration 回归：`JazorConsumerRoot` 指向同一 ASP.NET Core 项目内的 `consumer` 构建层，`JazorConsumerBuild` 在 `JazorEmit` 后调用 `consumer/scripts/run-deno.cs`，并把浏览器资产输出到 `wwwroot/jazor`。`JazorConsumerRoot` 已设置但 runner 缺失时会由 MSBuild target 直接 fail-fast，不进入 analyzer-private Razor SG fallback；Playground 的 colocated `consumer` 仍是单 ASP.NET Core 项目里的前端消费构建层，不是第二个 runtime host。
- route template -> Vue Router bridge 仍拒绝无法诚实映射的长尾形态：optional separator 参数不是 segment 尾部、没有紧邻前置 optional separator、需要多层组合展开的 composite/mixed segment，以及无法转换成“一个 Vue Router path regex + generated metadata 二次校验”的 constraint 组合。未知自定义 constraint、当前 ASP.NET Core 默认 `ConstraintMap` 不内置的 `date` 仍保持 fail-fast。

## 已从缺口移除

- Body-level imperative render 主线已覆盖 `return`、`while` / `do-while`、带 `break` / `continue` 的 `for` / `foreach`、`switch`、`lock`、`try/catch/finally`、`using` / `using declaration`、无 `goto` labeled statement、局部 mutation、静态 markup / `MarkupString`。
- 本轮补齐 root-only simple constant `switch` 的 canonical `<template>` 回流：switch governing expression 必须无副作用且 template-safe，case label 必须是稳定 scalar constant，每个 section 必须以 terminal `break` 结束且 body 能通过现有 BuildRenderTree parser / canonical template 预检；输出使用 template-scope 单次捕获 switch value，并生成稳定 `v-if` / `v-else` 链。合法空 case 分组（例如 `case 0: case 1:`）会合并成同一 `||` 条件分支；`return` section、`goto case/default` 显式跳转、声明 pattern 绑定局部的 switch、guard/pattern 含副作用或需要单次求值缓存的 switch、section 内 nested imperative / scoped replay / unsupported template expression 继续保守走 render-function 或 fail-fast。
- 本轮补齐 root-level terminal guard-return / `if/else` 单分支裸 `return;` 的 canonical `<template>` 回流：条件必须是无副作用、bool、template-safe 表达式；exactly-one branch 必须是裸 `return;`，另一 branch 与条件后的 tail 会按源码顺序合并为继续执行分支，并且 branch/tail 都必须能通过现有 BuildRenderTree parser 与 canonical template 预检。`if (Hide) return; tail`、`if (Hide) return; else body; tail`、`if (Show) body; else return; tail` 均可恢复为 `v-if` / `v-else` 模板。condition invocation、nested return、双分支 return 且无可达 template 输出、branch/tail mutation、scoped replay、async/exception/byref 或其它无法证明求值顺序和副作用次数等价的形态继续保守走 render-function 或 fail-fast。
- 本轮补齐受控 nested guard-return 的 canonical `<template>` 回流：恢复逻辑允许 root-level guard branch 内继续包含单分支裸 `return;` guard，只在所有 guard condition 都无副作用、bool、template-safe，branch body 可通过现有 parser / canonical template 预检，并且不需要把外层 tail 复制进多个分支时恢复为嵌套 `v-if` / `v-else`。嵌套 condition invocation、branch/tail mutation、双分支 return、需要跨分支复制 tail、scoped replay、async/exception/byref 或无法证明顺序/副作用次数等价的形态继续保留 render-function 或 fail-fast。
- 本轮复核 `goto` 边界：混合 render body 中无跳转的 labeled block 继续由 render-function bridge 承载；真实 `goto` 继续通过 `UnsupportedImperativeRenderLowering` fail-fast，诊断明确指向 Jazor.Compiler 缺少任意 jump control flow 的等价 JS lowering，不会被 render-function bridge 静默擦除。
- 本轮补齐 root-level no-op labeled block 的 canonical `<template>` 回流：恢复逻辑只接受单个 root `ILabeledOperation`，label body 不含 `goto` / `break` / `continue` / 显式 `return` / `throw`，且 body 可通过现有 BuildRenderTree parser / canonical template 预检；label 本身会被擦除为普通 template body。mixed labeled segment、真实跳转、label body mutation、exception/async/byref、scoped replay 或其它无法证明控制流可擦除的形态继续保留 render-function 或 fail-fast。
- 本轮补齐 root-level null/default `using` statement 的 canonical `<template>` 回流：恢复逻辑只接受单个同步 `IUsingOperation`，resource 必须可证明为稳定 `null` / `default(reference-or-nullable)`（允许无用户 operator 的 conversion 包裹），body 可通过现有 parser / canonical template 预检，且不含 branch / return / throw。真实 disposable resource、`using var` / `using declaration`、`await using`、resource initializer invocation / object creation / helper type declaration、body mutation、exception/byref、scoped replay 或任何需要真实 dispose/finally 语义的形态继续保留 render-function 或 fail-fast。
- 本轮补齐 root-level `do { ... } while(false)` 的 canonical `<template>` 回流：恢复逻辑只接受 `ConditionIsTop == false` 且 condition 可证明为稳定 `false` 的单个 root `IWhileLoopOperation`，body 不含 `break` / `continue` / `return` / `throw`，并且可通过现有 parser / canonical template 预检；body 会恢复为普通 template body。runtime-dependent `do/while`、普通 `while`、loop body mutation、loop control transfer、exception/async/byref、scoped replay 或无法证明单次执行的形态继续保留 render-function 或 fail-fast。
- 本轮补齐 root-level `while(false)` 静态零次执行的 canonical `<template>` 回流：恢复逻辑只接受 `ConditionIsTop == true` 且 condition 可证明为稳定 `false` 的单个 root `IWhileLoopOperation`，body 不含 `break` / `continue` / `return` / `throw`，并且可通过现有 parser / canonical template 预检；body 会包进 `<template v-if="false">`，保留明确 template block、source origin 与 HMR template identity，而不是生成空 template artifact。runtime-dependent `while`、body mutation、loop control transfer、exception/async/byref、scoped replay 或无法通过 canonical template 预检的 body 继续保留 render-function 或 fail-fast。静态零次 count-style `for` 仍走声明式 `RazorVueForNode` / `__jazorVueForRange(...)`，因为其本身有稳定 template 节点和 range helper identity。
- Imperative `AddComponentParameter(...)` 已按 descriptor 区分 prop / emit / slot；current-component slot forwarding、builder-style `RenderFragment` / `RenderFragment<T>` slot callback、nested component metadata/import 已进入正式路径。
- 静态 `OpenComponent(Type)` 及 source-stable local/current-component member `System.Type` carrier 已支持；这不是动态组件支持。
- Razor IR mixed attribute、lowercase `class` / `style` fallthrough、DOM event modifier、static markup、typed/untyped `RenderFragment` carrier、fragment factory、template local、setup/lifecycle helper 受控 payload、动态 `ShouldRender` cached render gate 已进入支持面。
- 本轮继续补齐 `ShouldRender` 的受控 delegate local compare：两个已跟踪 delegate local 的 `==` / `!=` 现在会按真实 JS 参考比较 lower；delegate null/default 检查、method group carrier、local lambda carrier 继续沿原合同处理，delegate 参数逃逸、非受控返回与重赋值仍保持 fail-fast。
- 本轮继续补齐 `ShouldRender` 的受控同方法局部函数 delegate 参数/返回流：`Func<int, bool> CreateReady() => value => value > 0; bool ConsumeReady(Func<int, bool> predicate, int value) => predicate(value); Func<int, bool> ready = CreateReady(); return ConsumeReady(ready, Value);` 会进入 cached render gate。支持面只接受同一 `ShouldRender` 方法内源码可分析的 local function：delegate factory 必须返回受控同步匿名函数，consumer 的 delegate 参数只能直接调用、与 null/default 判空或与同类 tracked delegate 作参考比较；delegate 参数返回、存入新 delegate local、跨 member / 外部调用、null/default initialized delegate invocation、delegate 重赋值和更一般动态 dataflow 继续 fail-fast。
- 本轮继续补齐 `ShouldRender` 的 NullOnly delegate 参数判空流：`Func<int, bool>? ready = null; bool IsMissing(Func<int, bool>? predicate) => predicate is null; return IsMissing(ready);` 以及 `default` 等价形态会进入 cached render gate。该支持只允许 null/default initialized delegate local 作为同方法局部函数 consumer 的参数，并且 consumer 内对应 delegate 参数只能参与 null/default 空值判断；一旦 consumer 调用该参数、返回/存储参数、跨 member 传递或发生更一般 dataflow，仍保持 `FullReloadRequired` / analyzer fail-fast。
- 本轮继续补齐 `ShouldRender` 的 tracked delegate local 声明后一次赋值初始化流：`Func<int, bool> ready; ready = value => value > 0; return ready(Value);`、同方法 local function method group、以及当前组件 private method group 的同类赋值初始化均会进入 cached render gate。该支持只接受顶层线性局部声明前缀中的未初始化 delegate local 后接 exactly-once 同步匿名函数或受控 method group 赋值；多次重赋值、分支赋值、赋值后逃逸、null/default invocation 和更一般 callable dataflow 继续 `FullReloadRequired` / analyzer fail-fast。method-group 赋值发射复用声明点初始化同一 RazorVue/SemanticWalker host seam，不回退到 `this.*.bind(this)` 这类不稳定运行时绑定。
- Runtime naming contract 已收敛：C# authoring surface 继续使用 `PascalCase`，Vue runtime/template 边界统一输出 `camelCase`，例如 `props.modelValue`、`item.title`、`item.isDone`。
- 本轮继续补齐 setup-side custom getter + private setter 的无后续写入形态：`private string Prefix { get => _prefix.Trim(); set => _prefix = value; }` 这类 getter 仍作为 setup `function prefix()` 发射，getter 表达式继续经 `RazorVueExpressionEmitter` / `SemanticWalker` lowering；setter 本身不进入 lowering 合同，源码中一旦存在 `Prefix = ...`、`ref/out` 写入或其它可观察 property 写入，继续 fail-fast，避免把可变属性时序误当成 source-stable getter。
- 本轮锁定 inherited source-stable setup member 的 lifecycle payload 支持面：base class 上的 declaration-initialized getter-only property 或 `readonly` field 可作为 `OnParametersSet*` / `SetParametersAsync` emit payload 的稳定 carrier，并继续先进入 setup/property/field lowering 主线，再在 watch body 内通过最终 setup binding 引用；base class public mutable property 仍按当前 non-parameter lifecycle payload 规则显式 unsupported，不会因为继承来源而被误判为稳定值。
- 本轮继续补齐普通 lifecycle 的 source-stable local-only / terminal-return no-op 形态：`OnInitialized()` / `OnParametersSet()` / `OnAfterRender(bool)` 等 lifecycle body 若只包含无副作用局部声明、空语句、no-op await expression statement、可选 terminal no-op return、terminal guard-return 或 terminal 双分支 `return;`，会被视为没有新增 runtime 行为，不生成 Vue hook/watch；HMR 边界仍由组件是否已有 setup/value member
