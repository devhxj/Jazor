# RazorVue 路线与边界

> Parent: [Jazor 架构转型开发计划](../Jazor%20架构转型开发计划.md)
> Size rule: keep under 10KB.

## 路线

当前产品路线：

```text
.razor / .razor.cs
    -> official Razor Source Generator
    -> generated .razor.g.cs
    -> Roslyn IOperation
    -> Jazor.Compiler / SemanticWalker
    -> direct Vue h()/Fragment VNode emitter
    -> Vue 3 render-function .mjs
    -> manifest
    -> Deno or Netpack
```

## 为什么是传统 Vue

当前目标是复用 Vue 生态，尤其是 Vuetify。传统 Vue render-function/VNode 与 Vuetify、Vue Router、Pinia、手写 SFC 的互操作成本最低。RazorVue 长期 production lowering 应接近 Vue compiler 输出形态：supported `BuildRenderTree` 调用直接降成 `h(...)` / `Fragment` / 后续 `createStaticVNode`、`mergeProps` 和 slot function code。

render-context v1 保留为 oracle/过渡层，用于尚未 direct lowering 的 supported surface、行为对照和负向诊断测试；不再作为长期主线的 frame stack runtime。

SolidJS direct-DOM/fine-grained 路线可以单独开线评估，但不混入当前 RazorVue/Vuetify 主线。

## 输入合同

生产输入只接受：

- official Razor SG generated C#；
- hook callback 可见的 Roslyn compilation；
- 在同一 compilation 派生链上补齐 missing generated trees 后取得的 `IOperation`；
- official SG source mappings。

禁止事项：

- 不读取 Razor DR/IR；
- 不把 `.razor` 原文重新解析为生产输入；
- 不 nested-run Razor SG；
- 不从零创建项目 compilation；
- 不在 analyzer 内私自写磁盘、启动工具链或访问网络。

## 输出合同

RazorVue 只输出：

- Vue render-function `.mjs`；
- `.mjs.map`；
- schema/versioned manifest；
- direct emitter 必要的 Vue runtime imports；
- 过渡期 `@jazor/vue-runtime` render-context assets。

`.mjs` 是最终 Vue component module，不是待二次解释的 wrapper 协议。slot、event、props 和 bind 必须在同一 lowering 中映射成最终 Vue runtime shape。

## 禁止路线

当前主线不实现：

- Razor template/SFC 反推；
- Jolt 协议；
- 自有 Blazor DOM diff runtime；
- 手写 DOM patch 模型；
- wrapper marker transport；
- 在一次构建中改走另一套 runtime 或 toolchain；
- 未经显式计划的兼容层。

## 诊断原则

无法表达的 generated-code shape 必须：

- 在 compiler/analyzer/render-context 边界给出明确 diagnostic；
- 写入未实现清单；
- 保持输出目录和 manifest 不声明半成品 artifact。

不得把 unsupported shape 当作普通 prop、普通 attribute 或普通 DOM child 静默处理。
