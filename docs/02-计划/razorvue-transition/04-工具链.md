# RazorVue 工具链计划

> Parent: [Jazor 架构转型开发计划](../Jazor%20架构转型开发计划.md)
> Size rule: keep under 10KB.

## 合同

`Deno` 与 `Netpack` 是两个显式工具链 lane。二者必须消费同一套 manifest/request/result contract。

```csharp
public enum FrontendToolchainKind
{
    Deno,
    Netpack
}
```

显式选择哪个实现，就只执行哪个实现。工具链接口不得在内部改用另一个 implementation。

## 统一输入

request 必须显式携带：

- manifest path；
- artifact root；
- source root；
- output root；
- build/dev mode；
- source-map/minify 配置；
- environment；
- required capabilities；
- version constraints。

实现不得从当前工作目录、全局 npm cache 或未声明环境变量推断输入。`.vue` / asset 只通过单向组件引用产生的 manifest 显式注册项进入工具链，不扫描 source root 猜测依赖。

## Deno lane

目标：

- production build；
- `.mjs` + manifest 显式注册的 handwritten `.vue`；
- `@vue/compiler-sfc`；
- CSS/assets/source-map；
- browser smoke；
- dev server/HMR。

G3 以 Deno production mixed SFC 作为必过项。

## Netpack lane

目标：

- production build smoke；
- `.mjs` + handwritten `.vue` source graph；
- Vuetify import smoke；
- source-map smoke；
- process cleanup；
- capability diagnostics。

Netpack 不引入第二套 artifact contract，不扫描目录猜入口，不改写 compiler-owned `.mjs`。未实现的 dev/HMR capability 必须返回 typed diagnostic。

## CLI / MSBuild

```text
jazor-toolchain build --toolchain Deno --manifest <path> --artifacts <path> --source-root <path> --out-root <path>
jazor-toolchain serve --toolchain Deno --manifest <path> --artifacts <path> --source-root <path> --out-root <path>
jazor-toolchain build --toolchain Netpack --manifest <path> --artifacts <path> --source-root <path> --out-root <path>
jazor-toolchain serve --toolchain Netpack --manifest <path> --artifacts <path> --source-root <path> --out-root <path>
```

| 属性 | 默认值 | 说明 |
|---|---|---|
| `JazorToolchain` | `Deno` | 显式选择 `Deno` 或 `Netpack` |
| `JazorBundle` | `false` | 是否执行 production build |
| `JazorBundleOut` | `$(OutDir)jazor` | bundle output root |
| `JazorDevServerHost` | `127.0.0.1` | dev server host |
| `JazorDevServerPort` | `0` | `0` 表示 OS 分配端口 |
