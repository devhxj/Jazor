## 合同

Netpack 是唯一的生产构建工具链。DenoHost 保留为生成模块的显式运行时执行器，不参与 browser bundle 的构建。

构建契约固定为一个 manifest/request/result 路径，不再暴露工具链选择项，也不得在内部回退到 Deno 或其他 bundler。

## 统一输入

request 必须显式携带：

- manifest path；
- artifact root；
- source root；
- output root；
- build/dev mode；
- source-map/minify 配置；
- environment；
- required capabilities；
- version constraints；
- referenced frontend library manifests。

实现不得从当前工作目录、全局 npm cache 或未声明环境变量推断输入。`.vue` / asset 只通过单向组件引用产生的 manifest 显式注册项进入工具链，不扫描 source root 猜测依赖。

Netpack 只消费 NuGet-owned frontend library resource graph。用户项目不提供 `node_modules`，构建也不得以 CDN 或 npm registry 作为输入。

## Netpack Lane

目标：

- production build smoke；
- `.mjs` 与 manifest 注册的 handwritten `.vue` source graph；
- Vuetify import smoke；
- CSS/static assets/source-map smoke；
- process cleanup；
- capability diagnostics。

Netpack 不引入第二套 artifact contract，不扫描目录猜入口，不改写 compiler-owned `.mjs`。未实现的 dev/HMR capability 必须返回 typed diagnostic。

## Runtime Boundary

DenoHost 负责调试、模块语义和 SSR 的显式运行时执行。它消费 materialized module graph 与 import map，不接管 Netpack 的 browser bundle 输出，也不作为 release build 的 fallback。

## CLI / MSBuild

```text
jazor-toolchain build --manifest <path> --artifacts <path> --source-root <path> --out-root <path>
jazor-toolchain serve --manifest <path> --artifacts <path> --source-root <path> --out-root <path>
```

| 属性 | 默认值 | 说明 |
|---|---|---|
| `JazorMode` | `none` | `none` 不输出；`debug` 输出模块；`release` 执行 Netpack production build |
| `JazorDir` | `$(MSBuildProjectDirectory)\wwwroot\jazor\` | debug 模块或 release bundle 的输出根目录 |
| `JazorDevServerHost` | `127.0.0.1` | dev server host |
| `JazorDevServerPort` | `0` | `0` 表示 OS 分配端口 |
