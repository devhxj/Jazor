# 前端封装库资源自包含方案

> Parent: [Jazor 架构转型开发计划](../Jazor%20架构转型开发计划.md)
> Status: implemented and reviewed
> Updated: 2026-08-06
> Size rule: keep under 10KB.

## 1. 结论

`ECMAScript.Vue3`、`ECMAScript.Vuetify` 等封装包必须携带其浏览器运行资源。应用消费者只执行 NuGet restore，不安装 Node/npm/pnpm，不维护 `package.json` 或项目级 `node_modules`，正常 build/publish 也不从 CDN 或 npm registry 获取资源。

正式交付物是包内已构建的 browser ESM、CSS、字体和图片，而不是原始 npm 包树。Deno 与 Netpack 只消费同一份本地资源图；`npm:` 仅可用于封装包维护者生成上游资源，不能进入应用生成模块、运行时 import map 或发布产物。

## 2. 原问题

迁移前 `[ECMAScript("npm:vue@3")]` 同时表达编译 import、包获取协议和运行时解析地址，导致三个边界耦合：

- Deno lane 设置 `nodeModulesDir = "auto"`，会自行物化 `node_modules`；
- Netpack lane 通过 source root 附近的 `node_modules` 解析裸包；
- debug 宿主需要手写 CDN import map；

这些路径能完成 smoke，但不满足封装包自包含和断网运行契约。

## 3. 最终产品契约

```text
PackageReference
    -> NuGet 恢复 binding DLL + browser assets + manifest
    -> Jazor.Emit 合并前端库资源图
    -> debug: 本地 ESM/import map/styles
    -> release: Deno 或 Netpack 消费同一本地资源图
    -> wwwroot/jazor 中仅保留本域可部署产物
```

硬约束：

- 用户侧不执行任何前端包管理命令；
- build/publish 不依赖项目、仓库或全局 `node_modules`；
- Deno lane 不联网解析 `npm:`，Netpack lane 不扫描 source root 找包；
- 浏览器请求不得指向 CDN、esm.sh 或 npm registry；
- 同一页面只有一个 Vue runtime，组件库预构建产物必须将 `vue` 声明为 external；
- 两个 lane 消费相同的库版本、import 映射、样式顺序和静态资源闭包。

## 4. NuGet 资源布局

资源直接进入对应封装包；若以后因体积拆出内部 `*.Assets` 包，也必须是自动传递依赖，公共使用方式仍只有一个 `PackageReference`。
封装项目的源码布局直接使用根 `manifest.json`、`dist/` 和 `licenses/`，不再设置无额外语义的 `frontend/` 中间目录。

```text
ECMAScript.Vue3.nupkg
├─ lib/net11.0/ECMAScript.Vue3.dll
├─ buildTransitive/ECMAScript.Vue3.targets
└─ jazor/vue3/
   ├─ manifest.json
   ├─ dist/vue.runtime.esm-browser.js
   ├─ dist/vue.runtime.esm-browser.prod.js
   └─ licenses/

ECMAScript.Vuetify.nupkg
└─ jazor/vuetify/
   ├─ manifest.json
   ├─ dist/components.mjs
   ├─ dist/labs.mjs
   ├─ dist/directives.mjs
   ├─ dist/vuetify.min.css
   ├─ assets/...
   └─ licenses/
```

Vuetify 等组件库使用 preserve-modules 或等价的 browser ESM 产物，保留 named export 和最终 bundler 的 tree-shaking 空间；不得把 Vue 打进组件库产物。

## 5. 库资源描述

`jazor/<library>/manifest.json` 使用逻辑模块名和相对包内路径，不保存 CDN URL：

```json
{
  "schemaVersion": 1,
  "libraryId": "vue",
  "version": "3.5.13",
  "imports": {
    "vue": {
      "development": "dist/vue.runtime.esm-browser.js",
      "production": "dist/vue.runtime.esm-browser.prod.js"
    }
  },
  "styles": {},
  "requires": {},
  "files": []
}
```

组件库的 `requires` 精确声明 Vue provider 版本，`styles` 按声明顺序列出 CSS。相同 `libraryId` 出现多个 provider 时直接返回 `JAZOR_LIBRARY_PROVIDER_DUPLICATE`；版本冲突、依赖环和缺失 logical import 同样返回稳定诊断，不进行隐式选择。

## 6. 编译与 catalog 边界

绑定统一生成标准裸 import，例如 `[ECMAScript("vue")]`、`[ECMAScript("vue-router")]` 和 `[ECMAScript("vuetify")]`。版本与物理位置属于资源描述，不属于 `ECMAScriptAttribute`。

`SemanticWalker` / `SenseArgument` / `AstConverter` 继续拥有 import 收集和稳定别名；catalog 在现有模块信息之外记录 external import specifier。RazorVue 从组件 descriptor 得到的 import 也进入同一列表。`Jazor.Emit` 依据这些显式 import 匹配资源 manifest，不通过正则扫描生成 JS 猜依赖。

样式只在库资源描述的 `styles` 中按库级顺序声明；需要额外样式的库应更新自身 `manifest.json` 与资源闭包。

## 7. 公共物化阶段

各包的 `buildTransitive` target 注册 `@(JazorLibraryManifest)`。`Jazor.targets` 将这些路径显式传给 `Jazor.Emit`；ProjectReference 构建使用同一 item contract。

`LibraryMaterializer` 在选择 lane 前：

1. 读取、校验并稳定排序所有资源描述；
2. 合并 logical import、版本要求和样式依赖；
3. 只从 manifest 所在包目录复制文件到独立 intermediate root；
4. 生成本地 import map、style list 和发布 `manifest.json`；
5. 对缺失 import、版本冲突和产物 hash 冲突返回可定位诊断。

该阶段不得从 current directory、source root、全局 cache 或环境变量推断资源。

## 8. Debug 与宿主

`JazorDebug` 在写出 `.mjs`/manifest 后执行公共物化，输出：

```text
wwwroot/jazor/
├─ components/*.mjs
├─ vendor/<library>/<version>/*
├─ importmap.json
└─ manifest.json
```

ASP.NET Core 宿主从生成清单渲染本地 import map 和 stylesheet link。`JazorAdminShell` 删除手写 jsDelivr/esm.sh 映射。原始组件库包通常不能直接由浏览器消费，因此 debug 必须使用包内预构建 browser ESM，不能直接暴露 npm source tree。

## 9. Release 两条 lane

### Deno

- 生成仅指向 intermediate 本地文件的 import map；
- 移除 `nodeModulesDir = "auto"`，不使用 `npm:` 和网络；
- 从本地 ESM 生成 `bundle.js`/source map。

### Netpack

- 仅打包应用生成模块，并保持 `ExternalPackages = true`；
- 包内第三方 ESM 原样复制到 `vendor/<library>/<version>/`，不交给 Netpack parser/printer；
- 将应用和 vendor 模块中的裸 import 后链接为 manifest 指定的本地相对路径；
- 不从 source root 或 `node_modules` 推断包，也不得回退调用 Deno。

公共样式物化保持 CSS 相对目录结构并复制字体/图片；`manifest.json` 按依赖拓扑和库内声明顺序列出 stylesheet。封装包生成阶段必须消除 CSS 内的外部 URL。

| P0 | schema、MSBuild item、catalog external imports、typed diagnostics | 已完成 |

封装资源生成使用 `scripts/csharp/` 下的单文件 C# 工具，固定上游版本、生成 hash/manifest 并携带许可证；用户应用构建不执行该工具。

## 11. 验收 Gate

- 外部 NuGet consumer 只 restore .NET 包；仓库和项目均无 `node_modules`；
- Deno 与 Netpack 分别完成 Vue/Vuetify release browser smoke；
- debug browser smoke 在禁止外网时通过；
- 输出 HTML、import map、JS、CSS 中无 `cdn`、`esm.sh`、`jsdelivr`、`npm:`；
- Vue runtime 单实例，Vuetify 未内嵌第二份 Vue；
- CSS 字体和图片请求全部命中本地静态资源；
- 重复 provider、版本冲突、缺失 logical import 均产生稳定诊断；
- package content 测试确认 DLL、manifest、ESM、CSS、assets 和 licenses 同时进入 nupkg。

## 12. 复核评审

结论：方案已按 NuGet-only consumer 契约落地。Vue3、Vue Router、Vuetify、Pinia、Element Plus 与 TDesign 均携带本地 ESM、样式和许可证；应用构建不需要 Node、npm、pnpm、项目 `node_modules` 或网络下载。

评审修正：早期“把完整 npm 包闭包物化给两个 bundler”的设想不适合作为最终交付面。它会把 package exports、源码转译和 CSS/Sass 差异推迟到用户构建期，并且 debug 浏览器不能直接消费。最终方案改为封装包携带预构建 browser ESM/CSS，consumer toolchain 只做本地解析、组合和发布。

复核发现 Netpack 0.6.0 的 parser/printer 会破坏 Vuetify 使用的现代语法，例如 async method 与空值合并表达式。因此最终边界不是逐条修补第三方源码，也不是依赖 alias 让 Netpack 解析 vendor；而是只打包应用模块，第三方 ESM 本地外置并在打包后链接。真实 Vue SFC 与 Vuetify browser smoke 已证明该路径可运行，vendor 二进制资源按字节复制。

命名复核同步移除了实现中的重复语境：资源入口统一为 `jazor/<library>/manifest.json`、`@(JazorLibraryManifest)` 与 `--library-manifest`；物化和工具链类型使用 `LibraryMaterializer`、`Toolchain`、`DenoBundler`、`NetpackBundler`；应用入口为 `/jazor/app.mjs`。目录或命名空间已表达的 `Frontend`、`RazorSg`、重复产品名前缀不再进入新增内部类型名。

非目标：本方案不实现通用 npm client、CDN fallback、运行时远程下载、任意 package.json 兼容层或第二套 Deno/Netpack artifact contract。
