# Jolt npm metadata

`NpmVueMetadataProvider` finds the nearest consumer `package.json` from a `.jazor` document path, restores its dependencies with the repository's pnpm API, and uses a tool-owned TypeScript 5.9.3 installation. The consumer declares Vue and the component package in its manifest.

`ListSpecifiersAsync` discovers the package root and explicit public subpaths. When Jolt resolves an `@using`, it checks matching directories in wildcard export targets for the requested namespace. For example, `@using Monaco = Npm.MonacoEditor.Editor.EditorApiJs.Exports` resolves `monaco-editor/editor/editor.api.js`. Callers can also send a concrete matching subpath to `ListExportsAsync` or `ReadAsync`. Export names use the npm name verbatim, including `default`. `NpmNames` translates those names to the Jolt namespace and tag convention.

`ReadAsync` returns props, emitted event signatures, slot signatures, and source definitions from public Vue declaration types. Definition offsets use UTF-16. Generic callable component metadata uses TypeScript's structural inference, so an unresolved type parameter can appear as `unknown`. The provider resolves the runtime entry through the ESM loader and reads export information through declaration files. Component runtime code is evaluated by the render consumer.

`ReadValueAsync` resolves functions, scalar constants and callable members of exported namespaces from a public ESM entry and its TypeScript declarations. Metadata preserves the authored module specifier, installed package version and definition spans. The checker reads declarations without evaluating package JavaScript. The generated C# distinguishes constants from functions and reuses existing host types for standard JavaScript dates, arrays, promises, supported DOM interfaces and Vue refs.

The projected API represents calls the declaration admits. For example, `Npm.DateFns.Exports.AddDays(date, 1)` returns an `ECMAScript.Date`. The checker instantiates the upstream date generics before Jolt projects the result. An unsupported trailing optional parameter can leave a shorter callable signature. Earlier TypeScript overloads with a different result can rule out an otherwise plausible C# overload. Unresolved generic relationships, rest parameters and explicit `this` parameters can still prevent projection.

For date-fns 4.4.0, `EachDayOfInterval(new() { Start = start, End = end }, new() { Step = 2 })` returns every other day. `Clamp` accepts the same date endpoint fields. `Min` and `Max` share one mutable `DateOrNumberOrString[]` input. Its native C# union preserves the upstream element domain during type checking and erases to the original JavaScript values.

For a composable with defaulted type parameters, the checker resolves the actual zero-argument call. This gives `useI18n()` its Composer and `useForm()` its form context. Overloads that take options need independent inference. A returned callable can expose a string-key overload when its type parameter accepts every string and overlapping overloads agree on the result. This permits `composer.T("greeting")` alongside the writable computed `composer.Locale`.

An options object supplied by C# can omit optional properties. A result supplied by JavaScript can expose the properties whose types Jolt can represent. The direction reverses for callback arguments. Ref read/write types and array mutability constrain the projection further because the caller and the package may share the same value. Reading an unsupported member of a partially projected result produces a C# diagnostic.

`ListValueExportsAsync` lists candidate names. `ReadValueProjectionsAsync` resolves all requested names for a module in one checker invocation and returns each supported signature or diagnostic. `ReadValuesAsync` returns the supported signatures for completion. Value snapshots persist under the consumer's `.jazor/cache/npm-metadata`. Cache validation resolves the runtime entry and checks the lockfile, npm configuration and declaration inputs, including previously missing TypeScript resolution candidates. A different checker toolchain gets its own entries.

Jolt.Compiler caches generated C# under `obj/Jolt/projections` using the normalized export selection, resolved signatures, declaration identities, and compiler and host versions. The component symbol table maps offsets in the generated C# to declaration indices. A cache hit rebinds those indices to the current TypeScript locations, so editing a declaration comment preserves the generated code and updates navigation. Public bindings can be materialized into an independent class library. [Cache verification](../../scripts/csharp/verify-jolt-projection-cache.cs)

For a local SFC, Vue Language Tools and TypeScript derive the public props, models, events and slots. The checker reads unsaved editor buffers and can resolve a `.jazor` import against the project's current generated TypeScript declaration. A later edit to that declaration invalidates dependent Vue contracts. Disk fingerprints record the bytes actually read by the checker so a second save during a query invalidates its result on the next lookup.

For saved Vue 3 HTML templates with the standard compiler plugins, the provider can reuse a contract after a literal text edit. It compares Vue parser text spans after the last mapped public definition and checks the other source and dependency inputs. A changed binding, slot expression, script or definition offset triggers a full query. Vite applies the template edit to the running component. [Mixed edit benchmark](../../samples/Jolt.Mixed/EditFeedback-baseline.md)

`dotnet run --file src/Jolt.Npm/verify.cs` covers published Reka UI components, the `es-toolkit/string` subpath, VueUse `useCounter`, default and named exports, overloads and callbacks, and cache invalidation after a dependency upgrade.

`dotnet run --file scripts/csharp/verify-jolt-binding-projection.cs` inventories the overloads, delegate signatures, public types and members in the seven handwritten bindings. It compiles the generated facade and reports which generated methods, properties and enum members the C# samples select, with the corresponding source lines. The Vue and DOM entries of Floating UI are checked separately.

`dotnet run --file scripts/csharp/verify-jolt-npm-runtime.cs -- <Jolt CLI apphost>` exercises date-fns, VueUse, Floating UI positioning and resize cleanup, VeeValidate field validation and typed form submission and typed Vue Query callbacks. Append `--browser <Chromium executable>` to verify the Monaco editor, model identity, worker RPC, disposal, theme and marker ownership with `jolt dev`. `dotnet run --file scripts/csharp/verify-jolt-composable-runtime.cs` covers locale changes, field errors and invalidation of active queries by exact or prefix keys. `dotnet run --file scripts/csharp/verify-jolt-floating-vue.cs` verifies positioning from read-only Vue element refs, replacing the anchor and unmounting. Run `dotnet run --file scripts/csharp/verify-jolt-i18n-plugin.cs` to create, install, render and dispose a Vue I18n plugin from C#.

`dotnet run --file scripts/csharp/verify-jolt-public-projection.cs -- <Jolt CLI apphost>` generates public declarations with `jolt bindings`, builds a .NET library and its consumer separately, then executes the consumer's emitted imports and async DTO query against the pinned packages.
